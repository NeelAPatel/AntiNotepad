# Third-party stack and carousel assessment

Checked 2026-10-17. Sources establish implementation candidates, not a working spike. Moving branch sources and web caches may differ from released packages; exact dependency source must be checked during restore.

## A: Avalonia + AvaloniaEdit

**Editor:** AvaloniaEdit supplies normal source editing, folding and line numbers. Its [demo](https://github.com/AvaloniaUI/AvaloniaEdit/blob/master/src/AvaloniaEdit.Demo/MainWindow.axaml.cs) installs TextMate, uses a `DocumentColorizingTransformer`, and demonstrates inline controls through `TextView.ElementGenerators`, `VisualLineElementGenerator` and `InlineObjectElement`. These are useful seams for styled Markdown and a clickable checkbox while keeping text canonical. A transformer styles text; it does not itself create interactive controls. A generic adorner overlay must also track wrapping, scrolling and hit testing. The demo is not a finished Markdown widget implementation.

The documented TextMate setup selects a grammar for the editor. A Markdown grammar may embed supported languages, but arbitrary fenced-language coverage is not established merely by installing TextMate: smoke-test Python inside Markdown and verify grammar injections, or add a range-aware highlighter. Checkbox source-range tracking, marker visibility, selection indentation and undo are application integration. See [README/setup](https://github.com/AvaloniaUI/AvaloniaEdit/blob/master/README.md), [color transformer](https://github.com/AvaloniaUI/AvaloniaEdit/blob/master/src/AvaloniaEdit/Rendering/DocumentColorizingTransformer.cs) and [element generator](https://github.com/AvaloniaUI/AvaloniaEdit/blob/master/src/AvaloniaEdit/Rendering/VisualLineElementGenerator.cs).

**Windows shell:** Official [Windows documentation](https://docs.avaloniaui.net/docs/platform-specific-guides/windows) covers `TransparencyLevelHint` values `Transparent`, `AcrylicBlur`, `Mica`, transparent Background, `ActualTransparencyLevel`, chrome removal with `WindowDecorations=None`, and native tray menus. Probe each material separately, including fallback/text clarity. Use `TrayIcon`; retain the initialized window while hidden. The same guide says the .NET SDK is sufficient for ordinary Windows development.

**Global hotkey:** Focused `KeyBinding` is insufficient. Prefer a small Windows-native layer using [RegisterHotKey / WM_HOTKEY](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey), unregister on shutdown, and report registration collisions. Avalonia exposes [Win32Properties WndProc hooks](https://github.com/AvaloniaUI/Avalonia/blob/main/src/Avalonia.Controls/Platform/Win32Properties.cs). This avoids a new hotkey dependency; HWND lifecycle and focus activation still need a real smoke check.

**Maintenance:** NuGet lists [Avalonia 12.1.4, updated 2026-10-09](https://www.nuget.org/packages/Avalonia), [Avalonia.AvaloniaEdit 12.0.0, 2026-04-08](https://www.nuget.org/packages/Avalonia.AvaloniaEdit), and [AvaloniaEdit.TextMate 12.0.0, 2026-04-08](https://www.nuget.org/packages/AvaloniaEdit.TextMate). Editor packages require Avalonia >=12.0.0; TextMate also brings TextMateSharp/Grammars >=2.0.3. These are candidates to pin together, not a verified restore/build. The [editor issue list](https://github.com/AvaloniaUI/AvaloniaEdit/issues) shows August 2026 reports and outstanding clipboard/undo/scroll issues. Core Avalonia has broad platform/API guides; editor documentation is more README/demo/source-driven. Adequate for a disposable spike, with editor integration risk.

## B: GPUI + GPUI Kit

**Identity/version:** GPUI is Zed's Rust UI framework; GPUI Kit is Longbridge's toolkit, whose styled layer is `gpui-component`. They are different projects. [Kit v0.7.3, released 2026-10-12](https://github.com/longbridge/gpui-kit/releases), pins the default GPUI snapshot to `gpui-pre` family **0.3.9**, Zed revision **93d7456**. The [tagged manifest](https://raw.githubusercontent.com/longbridge/gpui-kit/v0.7.3/Cargo.toml) and lockfile should govern the spike. Keep the optional GPUI Fast backend out of the initial comparison: it is another backend to validate.

**Editor:** [Kit Editor docs](https://gpui-kit.com/component/editor/) describe Tree-sitter grammar features, `.language(...)`, line numbers, folding, and text decorations. They explicitly say geometric range decorations are paint-only: no reserved inline space, widgets, pointer interception or focus. Do not equate these with clickable editor checkboxes. Source-preserving checkbox hit testing/rendering and heading style integration remain an extension to prove. Single-editor language selection alone also does not prove Markdown fence injection. Treat mixed Markdown/Python highlighting and wrapped interactive decorations as B's editor gates; rendered TextView Markdown is not evidence of editable source behavior.

**Windows/materials:** Upstream [platform types](https://github.com/zed-industries/zed/blob/main/crates/gpui/src/platform.rs) expose `WindowBackgroundAppearance::{Transparent,Blurred,MicaBackdrop,MicaAltBackdrop}` and titlebar/window options. The [Windows implementation](https://github.com/zed-industries/zed/blob/main/crates/gpui_windows/src/window.rs) maps Mica to DWM backdrop values and blurred mode to composition attributes. This is implementation evidence, not a supported Acrylic guarantee for Kit's exact pinned snapshot. Check chrome removal and each material on target hardware. Windows support is documented in Kit; GPUI remains [tied to Zed development](https://gpui.rs/), not an independent long-term compatibility promise.

**Tray/hotkey:** A [maintainer answer dated 2025-07-22](https://github.com/longbridge/gpui-kit/discussions/1077?sort=new) says GPUI/Component lacked tray support and suggests native APIs. That answer is historical; no current built-in tray/global-hotkey solution was established by this review. Plan Windows `Shell_NotifyIcon` and `RegisterHotKey` integration with a correctly owned message loop/dispatcher. Do not select another crate until a concrete native integration problem appears.

**Maintenance/docs:** Kit's [release notes](https://github.com/longbridge/gpui-kit/releases) include editor/input fixes and a yanked v0.7.2 replaced by v0.7.3. Its [issue list](https://github.com/longbridge/gpui-kit/issues) has new reports through 2026-10-16, including editor horizontal-scroll and Markdown selection conflicts. Active maintenance, but substantial API movement. Kit's installation/component guides are useful; upstream GPUI often requires source/examples. Good enough for a bounded spike, not evidence of scratchpad stability.

## Mandatory carousel: exact APIs and limits

| Input | A | B |
|---|---|---|
| Mouse drag | `PointerPressed/Moved/Released`, capture and capture-loss handling. Translate from initial pointer displacement; sample time/position for velocity. | Mouse-down/move/up handlers and drag state; translate from initial displacement; sample time/position for velocity. |
| Horizontal wheel | `PointerWheelChanged`, `Delta.X`; normalized wheel units, not physical content pixels. | `on_scroll_wheel`, inspect `ScrollDelta::Lines` vs `Pixels`; ordinary wheel input is not proof of a gesture lifecycle. |
| Windows Precision Touchpad | Reviewed Win32 path produces wheel deltas with no explicit contact/release phase. Public scroll recognizer is touch/pen, not the PTP wheel stream. | Reviewed upstream Windows Direct Manipulation path produces logical pixel deltas and `TouchPhase`; stronger basis for smooth direct motion, but `Ended` is not necessarily finger lift. |
| Release distance + velocity | Mouse/touch can supply it. PTP requires native lifecycle integration or a documented relaxation; a wheel timeout is heuristic. | Public phase stream reviewed does not expose the transition into inertia; native lifecycle access or a backend extension is needed to decide at finger lift. |
| Rubber band / create note | Application transform/spring/threshold logic; gate creation on an authenticated gesture end, once. | Same. Stock snapping Carousel is not proof of the requested release behavior. |

**A evidence:** [ScrollGestureRecognizer source](https://github.com/AvaloniaUI/Avalonia/blob/main/src/Avalonia.Base/Input/GestureRecognizers/ScrollGestureRecognizer.cs) tracks only touch/pen in PointerPressed. It emits scroll deltas, `ScrollGestureInertiaStarting` with velocity and `ScrollGestureEnded`; Ended may follow inertia/capture loss. [Win32 wheel handling](https://github.com/AvaloniaUI/Avalonia/blob/main/src/Windows/Avalonia.Win32/WindowImpl.AppWndProc.cs) divides by **120.0**, preserving fractional wheel units; do not call it integer truncation. Neither establishes raw PTP contact phases or 1:1 physical translation. Timestamped wheel samples plus an idle timer cannot distinguish a paused finger from lift/inertia.

**B evidence:** [Upstream Direct Manipulation source](https://github.com/zed-industries/zed/blob/main/crates/gpui_windows/src/direct_manipulation.rs) recognizes `PT_TOUCHPAD`, enables translation/inertia and emits `ScrollWheelEvent` pixel deltas with Started/Moved. It ends a sequence at READY, or when new RUNNING interrupts INERTIA; it does not emit finger-lift on RUNNING → INERTIA. Sampling until Ended therefore estimates post-inertia motion, not release velocity. The exact **93d7456** source fetch was unavailable to this review; verify the restored snapshot before assuming even this behavior. API names alone are insufficient.

Kit's [Carousel docs](https://gpui-kit.com/component/carousel/) describe drag/trackpad snapping to the nearest point at gesture end and one item per wheel notch; edge gestures can bubble outward. They do not establish release-velocity selection, custom rubber band, or pull-to-create behavior. Reuse only after checking these semantics.

**Shared fallback:** Microsoft [InteractionTracker](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.composition.interactions.interactiontracker) exposes Interacting/Inertia states; native [touchpad-capable registration](https://learn.microsoft.com/en-us/windows/win32/input-precisiontouchpad/registertouchpadcapable) plus Interaction Context is another Windows route. These are targeted native input candidates, not drop-in managed/Rust integrations. Prove supported OS/API availability, cancellation, DPI, direction settings, and editor event arbitration before calling either spike a pass.
