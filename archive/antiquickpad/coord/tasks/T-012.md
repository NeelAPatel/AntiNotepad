## User's requirement (verbatim intent)
"Codebase should be modular so changing one component or feature doesn't hurt anything else. MVVM perhaps. Keep UI separate from backend as much as possible with function calls, so we can change rendering, scrolling and other user-facing features without changing the backend unless necessary."

## Target structure
1. `src/AntiQuickPad.Core` (classlib, net10.0, NO Avalonia reference): Note, NotesSession/store, atomic persistence, settings (pin, window bounds, chosen shell/look id), note commands (Create, Delete, Select, Next, Previous, UpdateText, UpdateCaret, Save, Flush), save-state events, list-continuation and indent text operations if they are pure text transforms, markdown scanner if it can be pure (no Avalonia types). Public API = methods + events + plain records. Unit-free; keep smoke checks.
2. `src/AntiQuickPad` UI layer:
   - `ViewModels/`: MainViewModel (notes list, current index, count text, save state, pin, commands), NoteViewModel, StatusViewModel. Only these talk to Core. Plain INPC + RelayCommand helpers you write.
   - `Shell/` platform services behind interfaces (IHotkeyService, ITrayService, ISingleInstanceService, IWindowPlatform for show/hide/topmost/bounds) so views and VMs never call Win32 directly.
   - `Views/`: an `IShellView` contract (host the editor, bind bars to MainViewModel commands/properties, show/hide hooks) and the CURRENT shell moved into one implementation (`Views/Classic`). Next task adds `Views/Quiet` and `Views/Card` as siblings; a shell switch must not need Core/VM changes. Design-harness code (src/AntiQuickPad/Design) should reuse the same contract where practical.
   - `Editor/`: AvaloniaEdit factory + renderers stay UI-side, configured by Look/DesignSpec; they read document text and call VM/Core operations for edits (checkbox toggle, list continuation) instead of owning business rules.
   - `Carousel/`: animation/gesture only; it asks MainViewModel to select next/previous, never touches the store.
3. Composition root in App/Program wires Core -> VMs -> chosen shell. No service locator magic; constructor injection by hand.
