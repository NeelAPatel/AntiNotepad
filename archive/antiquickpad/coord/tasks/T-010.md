## Goal
A repeatable baseline so later UI/animation work (M6) can be checked for regressions. Budget: hotkey-to-visible-and-focused < 100 ms.

## Harness: `AntiQuickPad.exe --measure [--samples N] [--out file.json]`
- Launches a SEPARATE resident child of the Release exe with an isolated data dir, isolated singleton names, and an alternate hotkey (e.g. Ctrl+Alt+F9 via ANTIQUICKPAD_HOTKEY) so the user's real pad and notes are untouched. Add whatever flags/env this needs (e.g. `--instance <name> --data <dir>`), documented.
- Sends the real chord with SendInput (keyboard path, not an internal call). Shared clock: QueryPerformanceCounter in both processes; the child logs QPC at WM_HOTKEY, at editor focus, and at the first rendered frame after show (Avalonia RequestAnimationFrame / render callback after Show). Harness records QPC just before SendInput.
- Metrics per sample: input->WM_HOTKEY, input->focused, input->first frame painted; hide (Esc via SendInput) -> window hidden. Also: cold start (process start -> first frame), idle working set + private bytes after 30 s idle, idle CPU % over 30 s hidden and 30 s shown, and after creating 20 notes with ~200 lines each (a heavier state).
- 30 samples default, 300 ms apart, discard first 3 as warm-up. Report min / median / p95 / max.
- If SendInput or foreground activation is blocked in your sandbox, say so precisely, still build the harness, run every metric you can, and leave the rest for the manager to run outside the sandbox (give the exact command).
