# T-010 — M5 Release speed baseline

Implementation and standalone measurement complete, 2026-10-18. Input timings blocked by sandbox; baseline documents exact gaps and outside-sandbox rerun. Final Release build and full selftest passed; report complete.

## Implementation

- `src/AntiQuickPad/Measurement.cs`: `--measure [--samples N] [--out file.json]`, default 30 total attempts with the first 3 discarded as warmups per state (up to 27 retained), minimum 300 ms between completed cycles. Statistics are min/median/nearest-rank p95/max, with nulls for unavailable endpoints. Parent sends the real Ctrl+Alt+F9 chord and Esc through Win32 SendInput; it never substitutes internal calls for timing samples.
- Separate apphost child, unique singleton ID and unique data directory, alternate hotkey via child-only environment override. Private launch flags: `--measure-child --instance <id> --data <directory>`. No ordinary singleton acquisition in the harness; notes/settings/logs all isolated under `bin/Release/net10.0/measure/<GUID>`.
- Program dispatches measurement before ordinary residency. MainWindow probes log shared-clock events at WM_HOTKEY, foreground-confirmed editor focus, first RequestAnimationFrame callback scheduled after Show, and Hide return. Raw events include QPC ticks; parent records QPC immediately before input injection. Stopwatch.GetTimestamp at WM_HOTKEY is Windows QPC. Callback timing is explicitly not proof of paint/presentation.
- Empty-note and heavier 20-note / 200-line states in the same resident; fixture persisted through NotesSession and real editor binding. Verified on disk: 20 .md files, all 200 lines. Four 30 s idle CPU/memory windows, with 1 s settling each; control-file show/hide is only used to establish idle states. Graceful child quit plus 10-minute graceful watchdog; no process killing.
- Selftest launches a real `--measure --samples 3` child, verifies exit 0, parses JSON and requires baseline/heavy state objects, allowing explicit sandbox input gaps. It includes full idle windows (~2.5 minutes overall). Existing proof outputs redirected to the isolated selftest directory so future selftests stay under src.

## Exact gaps / manager action

No WM_HOTKEY received; no foreground-confirmed focus event. Input sampling stops on the first blocked warmup in each state; actual retained n=0 despite requested n=30. Esc is not injected without confirmed foreground focus. All input->hotkey, input->focus, input->frame-callback and Esc->hidden distributions remain null. Resource metrics still run fully. These gaps are recorded in JSON; successful harness exit does not mean timing budget passed.
