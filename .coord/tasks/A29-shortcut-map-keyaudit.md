## Why
The user is designing the app's keyboard-shortcut set (item A29-shortcut-map). Editors already reserve many keys, so the set must not rebind keys that text boxes handle themselves. Example from the user: Shift+arrows selects characters in any text field, so it can never be an app shortcut. Alt+Shift+arrows may be rectangular selection in AvaloniaEdit. Dev copies own Ctrl+Alt+Shift+1~9 and Ctrl+Alt+Shift+F1~F9 (`AppInfo.DevSlot`); the global hotkey default is Ctrl+Alt+Shift+S.

## Answer these
1. **Editor defaults.** From the AvaloniaEdit 12 / Avalonia 12 packages the project uses (read the source or xml docs under the NuGet cache offline; if you cannot find them, say so), list every key combination the text editor and TextBox handle by default: caret movement, selection (Shift+arrows, Ctrl+Shift+arrows, Shift+Home/End), rectangular selection (Alt+Shift+arrows?), word delete, undo/redo, clipboard (Ctrl+C/X/V/A, Ctrl+Insert, Shift+Insert, Shift+Delete), line ops, Tab behaviors, Enter, Ctrl+Z/Y/Shift+Z. Table: key, what it does, where it comes from (file:line or type), does this app override it (file:line).
2. **This app's overrides and shadows.** For every key in `PadWindow.Keys.cs`, `PadView.OnKeyDown`, `ScrollableTopInset`, `Completion`, `SearchOverlay`: does it shadow an editor default or a Windows or browser-habit key? Specifically check: does the window-level Alt+Shift+Up/Down (move note) fire before or after AvaloniaEdit's rectangular selection or other handling, and can the editor see it first (tunnel vs bubble, `e.Handled`)? Same for Ctrl+Shift+[ ] fold, Ctrl+Shift+C, Ctrl+Shift+O, Ctrl+Home, Ctrl+Enter, Ctrl+, and Ctrl+\ .
3. **Never-bind list.** A table of keys the app must not offer as rebindable shortcuts, in groups: (a) text-editing keys any text field uses (Shift/Ctrl+arrows, Home/End, Backspace/Delete, Ctrl+A/C/X/V/Z/Y, Insert...), (b) Windows-owned (Win+*, Alt+Tab, Alt+F4, Ctrl+Alt+Del, Alt+Space, Ctrl+Esc, Alt+Esc, PrintScreen, Alt+Shift/Ctrl+Shift layout switch ...), (c) app-reserved (dev slot keys, global hotkey, Esc, Enter, Tab, fixed editor keys), (d) conventional meanings worth avoiding (Ctrl+W, Ctrl+Tab, Ctrl+S, Ctrl+P, Ctrl+O, Ctrl+B/I/U ...). For each, one line why.
4. **Safe space.** List the combinations that remain free and sensible as app shortcuts, by modifier group (Ctrl+letter, Ctrl+Shift+letter, Alt+letter, Alt+Shift+arrow ...), noting which are taken today.
5. **Recorder rules.** How `HotkeyRecorder.GestureText` and `IsCommand` decide what is recordable today (`UI/HotkeyRecorder.cs`), and what a shortcut-recording UI for in-window keys needs to refuse beyond that (list the rules).
