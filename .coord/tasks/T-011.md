## Problem
The user's words: the current UI "looks like a dev threw boxes in approximate areas to make it work". Goal: native-Mac-app (AppKit) level fit and finish on Windows 11. This is a frontend redesign, NOT colour themes. Speed of show/hide stays the top priority.

## Deliverable
Three clearly DIFFERENT design directions, each a real render of the real app UI (same Avalonia/AvaloniaEdit code paths, real editor with the real colorizer/checkbox/guide/strike renderers), not drawn mockups. Add `AntiQuickPad.exe --render-design <direction> <outdir>` that builds the window in that design, loads a fixed fixture, and saves PNGs via RenderTargetBitmap at scale 1 and 1.5.

Per direction, render these states (PNG each):
1. main: a realistic note (H1/H2, paragraph, bullets, nested checkboxes, a python fence, a struck line), caret on an indented line.
2. bars: top and bottom bar visible/hovered (window controls, New/Delete/Prev/Next/Pin, more-menu button, note count, save state).
3. menu: the more-menu open.
4. carousel: mid-slide between two notes.
5. empty: a brand-new empty note (placeholder/hint text).

Each direction must cover, in its own way: top bar + bottom bar layout (F4: designed so it can later become hover-reveal), icons (use the Windows 11 "Segoe Fluent Icons" font glyphs; no downloads), typography and spacing scale, active line highlight (F20), modern fold markers replacing the stock white boxes (F24: custom chevrons; replace or restyle the FoldingMargin), gutter treatment, code panel, checkbox, scrollbar styling, note-count / page indicator, corner radius and border/shadow treatment that works on an opaque standard window.

Directions (keep them distinct; refine names freely):
- A "Quiet": AppKit-like restraint. Minimal unified title/toolbar, small monochrome icons, generous margins, almost invisible chrome; the text is the UI.
- B "Card": carousel-first. Each note is a card with subtle elevation; neighbouring cards peek at the edges; page dots; bars float over the card.
- C "Pro": dense, keyboard-first, editor-like. Thin status bar with useful info (line/col, word count, save state), command-hint chips, compact toolbar.

Also, for each direction, write how motion would work (F5 window show/hide, F21 smooth scroll, F22 smooth caret, F23 animated folding) and how hard each is in Avalonia/AvaloniaEdit (easy / medium / hard / not feasible), without building the motion yet.
