## Why this round
User hand test, 2026-11-20 (verbatim):
1. "the states between active and dim isn't animated. it just snaps between them."
2. "the toggle between standard and permanent notes is trippy. I click and then the toolbars fade out when it should just stay there. If im hovering over any of the buttons on the toolbars, they should stay visible."
3. "Scrolling shouldn't kick me out of permanent notes. instead it should scroll among the slots of permanent notes."
Everything else the user tested works (corner buttons, hover colors, swap, delete debounce and Undo). Split-view changes the user also asked for (two bars, swap per active pane, three pairings) are a separate item: change nothing about split behavior here except what item 3 needs.

## Do
1. **Animate dimming.** When Delete or New note changes enabled state, fade the glyph/face opacity between 1 and `Paint.DisabledIcon` with an existing motion token (look in `Theme/`/`MotionTokens` for the button or chrome fade durations; add a token only if none fits) through `Anim.Run`; skip the animation when `Anim.Reduced`. Do it in the shared `Kit.IconButton` path (the `IsEnabled` handler from the last round) so every icon button benefits. Cancel a running fade when the state flips again; initial state must not animate on build.
2. **Chrome must not fade under the pointer.** Today `SleepChrome(soon: false)` (called after navigation, swap, delete, slot open: see `PadWindow.Navigation.cs`) fades the docked chrome even while the pointer is over the bar or the top row. Change `SleepChrome` in `UI/PadWindow.Layout.cs` so that while `_bar.IsPointerOver || _top.IsPointerOver` (any button in either), the chrome stays visible and the sleep timer is restarted instead of fading; when the pointer leaves `_bar` or `_top`, start the normal sleep timer in the docked "fade" setting (`Settings.Chrome == "fade"`; Overlay and Float already use `BarsSleepTick`). Typing still fades the chrome as before. Check the swap button case explicitly: clicking the swap button must leave the top row and the bar visible.
3. **Scrolling and previous/next inside slots cycle the slots.** In `Navigate(int direction)` (`UI/PadWindow.Navigation.cs`), a left pane showing a slot no longer calls `ShowStack()`: it moves to the next or previous slot among the 9 (wrapping 9 to 1 and 1 to 9, empty slots included, as `CycleSplitSlot` does for the right pane), skipping the slot shown in the right pane when split is on. The swap button, the `stack` shortcut and clicking the current dot still return to the stack. Swipe/wheel (`NoteSwipe` via `CanNavigate`) and Alt+Left/Alt+Right both use `Navigate`, so both cycle. Update the help text of `next-note` and `previous-note` in `UI/Shortcuts.cs` and the `docs/shortcuts.md` table row text to say that inside a slot they move between slots (the A29 checks compare the table and the docs; keep them equal). Update `_lastSlot` bookkeeping so swap returns to the slot you were on.
4. Selftests (small, in `SelfTest/Bar.cs`): Navigate in a slot cycles (1 to 2, 9 to 1, 1 to 9, skipping the right-pane slot in split), the stack stays reachable through `ShowStack`; `SleepChrome` does not fade while the bar or top row reports the pointer over (use the existing reflection helpers); disabled fade ends at `Paint.DisabledIcon`.
5. If the design dump changes, do NOT edit `SelfTest/Design.cs`; report it.
