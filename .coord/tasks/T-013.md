## Decisions (user)
- Build BOTH Quiet and Card, "built and well supported": the real resident app, not render fixtures. Classic stays as a fallback shell id.
- Each shell has a light AND dark palette. Default follows the Windows app theme (live: switching Windows theme updates the open app). Manual override in the More menu: Theme = System / Light / Dark. Persisted.
- Shell choice in the More menu (Quiet / Card), switchable at runtime without restart, persisted. Default shell: Quiet.
- UI stays separate from backend: shells bind to MainViewModel commands/properties only (see architecture.md).

## Per shell (match the approved renders; dark palette designed to the same standard, not an inversion)
- Window: unified in-client title/toolbar (ExtendClientArea) with the rendered controls: New, More, Pin, Minimize, Close (= hide). Drag region on empty toolbar space; keep Windows snap layouts/double-click maximize working. Bottom bar as rendered (Quiet: prev/next + "3 of 8", save state, Esc hint, delete; Card: floating pager with dots + exact count, save state).
- Bars: subdued when idle, full strength on pointer hover or keyboard focus (first step toward F4 hover-reveal; layout must not shift).
- Editor: production EditorFactory with the shell's Look; F20 active line highlight and F24 chevron fold margin in the real app (not design-only); typography/spacing per README.
- Carousel: existing gestures and 220 ms slide via MainViewModel. Card shows neighbour card peeks and moves the dots; Quiet slides the page. Dot range must handle >8 notes (sliding window).
- Empty note: hint text overlay as rendered.
- Menu: Theme (System/Light/Dark), Shell (Quiet/Card), Quit. Keyboard accessible.
- Show/hide path, focus-on-show, hotkey, tray, single instance, --quit, autosave, Pin, bounds restore must behave as today.
