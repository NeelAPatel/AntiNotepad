# T-012 — Core / ViewModels / Views refactor

Status: COMPLETE — final Release build, Core smoke, full selftest and all retained CLI entry points passed. Manager owns git. No git commands, network calls, new packages, process killing, shared STATUS/HANDOFF edits, or out-of-scope writes.

## Result

Package-free net10.0 Core owns notes, atomic persistence, settings and pure Markdown/text rules. UI ViewModels own note projections, commands, save/pin state and the settings adapter. The existing resident visual tree is now Views/Classic/ClassicShellWindow, implementing IShellView; Design shares its smaller IEditorHost contract. App constructs Core -> VM -> selected shell and injected platform services by hand. Only Classic is selectable today; Quiet/Card remain T-013. Unknown shell IDs fall back to Classic while retaining their stored identity.

The editor remains resident, its undo stack is cleared only on note binding, and text operations apply small Replace edits inside undo groups. Per-document VM routing avoids a static global edit callback. The UI scanner adapter maps Core metadata to Avalonia folding/rendering types. Carousel retains its original gate/drag/snap/preview behavior and selects through MainViewModel. The 350 ms dispatcher debounce, runtime scroll offsets and focus/animation stay UI-side.

Core has no UI package, project or assembly reference. Main/Note/Status VMs have no Avalonia dependency. Views do not open note/settings stores. Platform services own native hotkey/singleton/tray handling and window operation adapters; views and VMs never call Win32 directly. Classic still reads its own Avalonia visibility/normal-window state for focus and bounds capture; this is UI state, not backend logic.
