# A34-pill-bar-per-mode lens review

## Findings (proven)
1. [major] `product/AntiNotepad/UI/PadWindow.Bar.cs:75` and `:82` — Disabled Delete and New note do not look dimmed. `BuildPill` changes only `IsEnabled`. `Kit.IconButton` (`UI/Kit.cs:93`) constructs a `GlyphIcon` with a fixed ink brush; `GlyphIcon.Render` (`:47`) draws that brush independently of the disabled foreground supplied by Fluent. Neither `Kit.Plain` nor the new hover handling supplies disabled opacity or glyph ink. A hidden-window probe using the actual Fluent theme, applied templates and layout toggled each real button enabled/disabled: the glyph, face, ContentPresenter, button and every ancestor up to the window all retained opacity 1 in both states. Input is disabled, but the explicit Plan promises (sole blank note, empty slot, trailing blank note) have no visible disabled indication. Smallest fix: give these buttons a disabled visual state using a Theme opacity token, restoring it when enabled; verify both state transitions against the actual control template.
2. [minor] `product/AntiNotepad/UI/PadWindow.Layout.cs:731` — The save-failure card loses its shadow in Float and Quiet slot view. This unchanged consumer still reads `_pill.BoxShadow`, whose meaning changed in `UI/PadWindow.Bar.cs:87`: Float and Quiet now deliberately set it to default. `ShowSaveFailurePrompt` copies that empty value into the card. The hidden-control probe produced `QUIET shadow=none` followed by `PROMPT shadow=none`; Float follows the same assignment path. Smallest fix: obtain the dialog shadow from a palette-based shadow helper or an independently styled chrome control, rather than the pager's current decoration. This requires no changes to persistence or shutdown logic.
3. [minor] `product/AntiNotepad/UI/PadWindow.Bar.cs:29` — New non-trivial methods lack the required XML summaries: `InitializeBar`, `BuildBarButtons`, `ConfigureBarStyle`, `BuildPill`, `SelectBarSlot`, `DeleteFromBar`, `SwapTarget`, and `SwapView`; the new `BarContent` type also has no summary. The touched `UI/Kit.cs:1` still has no file-purpose header. These are concrete deviations from `.claude/rules/coding.md` (Comments 1–2, applies on touch). Smallest fix: add concise purpose summaries/header, without historical commentary or unrelated reformatting.

Live animation timing remains unverified.

Probe: selecting 4 changed right and active slot to 4; selecting occupied left slot 1 left right at 4. - **Delete/A30: cleared.** The debounce uses `Environment.TickCount64` and `ChromeTokens.DeleteDebounceMs=500`; selftests cover 499/500 ms. `DeleteCurrent` is unchanged in the diff, as are Store, Note, save and shutdown implementations.
