## F32 cause

The hint was a separate root overlay above the entire deck, rather than part of the moving document/page. Its only update was in status refresh and it examined the current editor. When an empty selected note exposed a nonempty neighbour during a drag/slide, the current editor was still empty: the overlay remained above the neighbour's text. Carousel motion had no hint invalidation/suppression path. New appearance contexts also defaulted to a visible hint until a later status update. The fix makes the bound document authoritative, defaults the overlay to hidden, refreshes explicitly on binding/appearance/text paths, and hides it for motion. The screenshot's precise original input sequence was not replayed; the concrete empty-source/nonempty-preview failure path is now a regression check.
