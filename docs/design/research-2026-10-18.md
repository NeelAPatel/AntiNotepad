# Design system and motion research (2026-10-18)

Answers F34. Sources at the end. Third-party summaries are marked as such.

## 1. What makes Mac apps feel "connected to the user"
- **Interruptible:** any moving element can be grabbed mid-flight and reversed; the new motion starts from the current on-screen value, not the target (Apple WWDC 2018 "Designing Fluid Interfaces", via third-party summary).
- **Springs, not fixed timelines:** a spring keeps its velocity when the target changes, so retargeting is smooth. Apple exposes two designer parameters (response, damping fraction) instead of mass/stiffness/damping.
- **Velocity carried through:** releasing a drag hands the finger's velocity to the spring; swapping one fixed animation for another causes a visible "brick wall".
- **Feedback on every input:** hover, press, drag acknowledge immediately; motion is short, purposeful, and replaced by crossfades when Reduce Motion is on (Apple HIG motion).

## 2. Design systems worth borrowing from
| System | Use for | Notes |
|---|---|---|
| Apple HIG | Motion behaviour, restraint, typography rhythm | Primary feel target. |
| Fluent 2 (Microsoft) | Windows-native details: title bar, snap, focus, Mica | Principles: functional, natural, consistent, appealing; larger elements get more time; reduced-motion versions expected. Official token values not confirmed in this pass. |
| W3C Design Tokens 2025.10 | How we store the system | First stable format (Oct 2025): themes (light/dark), aliases, OKLCH colour. Not a W3C standard, but stable for production. |

## 3. Avalonia options
- **Composition animations** run on the render thread (smooth, not blocked by the UI thread). Documented animatable properties: Offset, Opacity, Size. Implicit animations fire automatically when a property changes. Good for fire-and-forget transitions (page settle, menu open, hover fades).
- **They are keyframe-based**, so they don't carry velocity. For drag-connected motion (carousel, fold, caret) we need our own small spring solver stepped per frame (TopLevel.RequestAnimationFrame) that can be retargeted mid-flight. This is why today's page slide looks stepped: it is a UI-thread timer with no easing curve.
- **Theme libraries** (FluentAvalonia, SukiUI, Semi.Avalonia, Material.Avalonia): Avalonia calls these community themes "in varying stages of development". They restyle stock controls; our UI is mostly custom (editor, bars, carousel), so they would add a dependency without solving motion or editor styling. Recommendation: do not adopt one; build our own small token set.

## 4. Typography (F28 monospace)
- **iA Writer Mono / Duo / Quattro** (OFL-1.1, built on IBM Plex, from iA's GitHub): designed for prose in a monospaced feel. Duo widens only m/M/w/W, which reads better for paragraphs while keeping the mono texture. Requires attribution to iA Writer if used.
- Already on Windows: Cascadia Mono (current editor), Consolas. Other OFL options: IBM Plex Mono, JetBrains Mono.
- Recommendation: iA Writer Mono (strict mono) or Duo (near-mono) for prose, Cascadia Mono for code fences; manager fetches the font files (sandbox has no network).

## 5. Proposed plan
1. **T-014 fixes now:** F27 heading colours back, F28 mono font, F29 bigger fold hit targets, F30 page slide on a real eased curve (render-thread), F31 menu alignment, F32 hint-overlay bug.
2. **M6c design system:** one token file (colour, type scale, spacing, radius, elevation, motion: durations + spring presets) in the DTCG shape, both shells read only tokens.
3. **M6d motion system (F33):** small spring module (response, damping, carries velocity, retargetable, reduced-motion aware) + composition implicit animations for simple fades; then apply to hover/press/drag, carousel, folding, caret, scroll, window show/hide.
